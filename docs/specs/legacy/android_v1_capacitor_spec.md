# SPlayer Android 轻壳版 V1.5 Spec

## 1. 目标

做一个 **Android 独立 App**，基于现有 SPlayer 前端，使用 **Capacitor** 封装，复用现有 Oracle API，不依赖手机浏览器/PWA 入口。

V1.5 必须同时解决三件事：

1. **App 化**
   - 独立图标
   - 登录态持久化
   - 不受 Firefox 私密模式影响
   - 能正常安装、启动、使用
2. **移动端可用性**
   - 页面不遮挡
   - 不溢出
   - 不出现桌面布局硬塞到手机上的情况
   - 核心操作单手可用
   - 不明显费电
3. **播放稳定性与媒体控制**
   - 播放中途卡流时可恢复
   - 缓冲时系统媒体时间轴不乱走
   - 标准通知栏与锁屏媒体控制可用

---

## 2. 非目标

V1.5 不做这些：

- 原生后台播放 service
- 原生音频引擎迁移
- 本地下载管理
- 从其他 App 接收分享
- iOS
- 桌面端重构
- 复杂动画和大规模视觉重设计

先把 **“能正常像个手机 App 一样用，并且播放器稳定可控”** 做出来。

---

## 3. 技术路线

### 前端容器

- **Capacitor Android**
- 前端静态资源内置进 APK
- 继续使用现有 Vue 前端
- 暂时保留 **hash 路由**

### Android 调试包口径

- `remote`
  - 本地默认模式
  - 完全依赖你自己部署的 `/splayer/*`
- `embedded`
  - GitHub CI 默认调试包模式
  - 目标是 APK 内置当前 App 实际使用到的 API runtime
  - 当前实现进度以 `feature_implementation_comparison.md` 为准

### 后端

继续复用你现有部署：

- Oracle 服务器
- Nginx
- 网易云兼容 API
- 统一挂在 `/splayer/*` 根路径下的接口入口

### 接口地址

Android 版不再依赖 `vercel.app/api/netease` 代理链。
直接配置为你的 Oracle API 地址，例如：

```text
VITE_API_ROOT=https://your-domain.com/splayer
VITE_ANDROID_API_MODE=remote
```

后面如果 Oracle 上 HTTPS，再切成 `https://...`

## 4. V1 交付范围

### 必做功能

- 首页可正常浏览
- 搜索可用
- 登录可用
- 播放页可用
- 评论入口可用
- 歌单/详情页可用
- 歌词页可用
- 设置页可用
- 系统分享可用
- 登录态重开 App 后仍保留
- 标准通知栏与锁屏媒体控制可用

### 必做移动端 UI 修复

以下全部纳入 V1：

#### 4.1 全局布局

- 适配窄屏宽度 `360px ~ 430px`
- 适配高屏比例
- 处理状态栏/底部安全区
- 去掉桌面端固定宽高导致的裁切
- 避免横向滚动条
- 避免内容被底部播放器遮住
- 避免顶部标题栏遮住正文

#### 4.2 页面壳层

- 顶部导航高度收敛
- 底部播放器固定但不遮挡内容
- 主内容区高度改为可滚动布局
- 所有页面统一滚动容器，不混乱嵌套滚动

#### 4.3 列表类页面

- 歌曲列表行高适中
- 封面、歌名、作者、操作按钮不挤压
- 过长文本单行省略或双行截断
- 右侧更多按钮不被挤出屏幕
- 列表项点击区域至少 44dp 左右

#### 4.4 搜索页

- 搜索框固定可见
- 搜索建议与结果列表不遮挡
- 键盘弹出时布局不乱
- 输入时底部栏/弹层不盖住结果

#### 4.5 播放页

- 封面图在小屏下缩放合理
- 歌曲信息、进度条、控制按钮垂直排布
- 不出现按钮超出屏幕
- 歌词区可滚动且不与整体滚动冲突
- 评论与播放队列使用底部抽屉，不再依赖左右滑页

#### 4.6 弹窗 / 抽屉 / 菜单

- 桌面 Popover 改成移动端 **Bottom Sheet / Action Sheet** 风格
- 不再使用超宽对话框
- 操作菜单不出屏
- 关闭区域明确

#### 4.7 登录页 / 二维码页

- 登录卡片居中且可完整显示
- 二维码不被裁切
- 手机屏上按钮可点
- 二维码轮询状态提示不遮挡

#### 4.8 设置页

- 表单项垂直排列
- 开关、下拉、输入框在手机宽度下不压缩变形
- 设置组之间间距清晰

## 5. 移动端 UI 设计原则

### 布局原则

- **移动优先**
- 先保证 `390x844` 这类主流 Android 尺寸正常
- 再兼容更大屏
- 所有固定宽度桌面容器改成 `max-width + padding`
- 页面尽量单列布局

### 交互原则

- 单手优先
- 常用操作放底部更易点区域
- 弹出菜单优先底部动作面板
- 减少 hover 依赖
- 不依赖右键/悬停行为

### 文本原则

- 超长文本必须截断
- 歌曲名/歌手名不要把布局撑爆
- 不搞过小字号
- 中文优先保证可读性

### 性能/耗电原则

- 不播放时不轮询
- 页面隐藏时暂停非必要刷新
- 封面图懒加载
- 长列表虚拟化或分页加载
- 减少持续动画
- 不做高频重绘背景效果

## 6. 工程改造项

### 6.1 Capacitor 集成

新增：

- `@capacitor/core`
- `@capacitor/cli`
- `@capacitor/android`
- `@capacitor/share`

新增文件：

- `capacitor.config.ts`
- `android/`

新增脚本：

```json
{
  "build:mobile": "pnpm build:mobile:remote",
  "build:mobile:remote": "...",
  "build:mobile:embedded": "...",
  "cap:sync": "npx cap sync android",
  "cap:open": "npx cap open android"
}
```

### 6.2 构建链拆分

必须拆出 **mobile build**，不要继续复用 Electron 构建链。

目标：

- `build:web` 给 Vercel
- `build:mobile:remote` 给本地远程服务模式
- `build:mobile:embedded` 给 GitHub CI 调试包模式
- `build:mobile` 默认别名到 `build:mobile:remote`

`embedded` 的目标定义是“完全本地 APK”，但实际实现状态必须以对照表和取舍文档为准，不能跳过 provider 覆盖面验证。

### 6.3 平台桥接

抽一个平台层：

- 分享
- 外链打开
- 可能的存储能力检测

最少先做分享桥接：

- Web：`navigator.share`
- Android：`@capacitor/share`

V1.5 额外要求：

- Android 返回键由应用自己接管
- Android 媒体桥负责通知栏、锁屏卡片和媒体按钮控制

### 6.4 环境变量

新增移动端环境：

```text
VITE_API_ROOT=https://your-domain.com/splayer
VITE_ANDROID_API_MODE=remote|embedded
```

### 6.5 样式体系整改

重点检查这些反模式：

- 固定 `px` 宽高
- 固定视口高度但没考虑安全区
- `overflow: hidden` 滥用
- 弹窗宽度写死
- 桌面 sidebar 在手机上仍强行显示
- 底部播放器 absolute/fixed 但内容区没预留空间

## 8. 推荐的移动端实现手法

### 布局

- 主容器使用 `min-height: 100dvh`
- 结合安全区：
  - `padding-top: env(safe-area-inset-top)`
  - `padding-bottom: env(safe-area-inset-bottom)`
- 底部播放器存在时，内容区增加对应 bottom padding

### 响应式

建议至少 3 档：

- `<= 480px`：手机主布局
- `481px ~ 768px`：大屏手机 / 小平板
- `> 768px`：保留现有 Web/桌面布局

### 弹层

- 桌面 modal / popover 改为移动 bottom sheet
- 操作按钮竖排
- 支持手势关闭不是刚需，先保证不遮挡

### 字体与点击区

- 最小正文字号别太小
- 按钮高度和行高不要太压缩
- 触控目标不要太细碎

## 9. 验收标准

### 功能验收

- 首次安装后能正常启动
- 登录成功后重启 App，登录态仍在
- 搜索、播放、查看歌单正常
- 分享按钮能调起系统分享面板
- 锁屏与通知栏出现标准媒体控制

### UI 验收

以下情况全部视为不通过：

- 页面出现横向滚动
- 核心按钮被裁切
- 文字、封面、控件互相遮挡
- 弹窗超出屏幕
- 键盘弹出后输入框被挡住
- 底部播放器盖住正文内容
- 页面滚动卡死或双重滚动冲突明显

### 性能验收

- 冷启动可接受
- 首页首屏不明显卡顿
- 切后台后不持续异常耗电
- 长时间停留非播放页不应高频请求接口
- 缓冲时不应继续按系统时钟推进媒体进度

## 11. 你现在最值得注意的一点

这次不要把目标写成：

**“先打成安卓包，UI 后面再说。”**

应该反过来：

**“安卓壳 + P0 页面移动端可用性” 是同一阶段交付。**

否则你得到的只是一个“套了壳的坏网页”。

## 12. 最终建议

这版直接按下面这个定义推进：

**Capacitor Android V1 = 轻壳容器 + 移动端 UI 修正 + 登录持久化 + 系统分享**

后端不动。
前端主要做两类改动：

1. **构建与平台接入**
2. **移动端 UI 整理**

如果你要，我下一条直接给你更具体的开发清单：

- `capacitor.config.ts` 模板
- `package.json` scripts
- `vercel.json` 和移动端环境怎么分
- UI 改造的 CSS / 组件层 checklist
