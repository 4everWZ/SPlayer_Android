# Android Native V2 播放器文档

## 核心组件

- `PlaybackCoordinator`
- `TrackSourceResolver`
- `QueueRepository`
- `SPlayerPlaybackService`

## 对齐目标

原生播放语义对齐 `SPlayer desktop`，但当前主线仍通过 `remote API` 承接这些合同。核心是：

- 官方源优先
- 解锁源按启用顺序补位
- 当前歌曲失败音源记忆
- 重试上限按剩余可用音源动态计算
- 卡流恢复时保留当前稳定进度
- 不引入会员音质门槛或广告打断逻辑

## 音源链路

客户端保留故障转移链，不能假设单一源永久可用。Android 不启动桌面端 Node/Electron 本地 unlock 服务。

### 官方源

按顺序尝试：

1. `song/url/v1?level=exhigh`
2. `song/url/v1?level=higher`
3. `song/url/v1?level=standard`

### 解锁源

`unlockServerMode=LOCAL` 为默认模式，按需走 Android 原生网络解析：

1. `native-netease`

`unlockServerMode=EXTERNAL` 为外部服务器模式，按顺序尝试：

1. `unblock/netease`
2. `unblock/kuwo`
3. `unblock/gequbao`
4. `unblock/bodian`

### 失败记忆

- 当前歌曲已失败的音源必须进入失败记忆
- 下一轮恢复时优先跳过已失败音源
- 手动清理失败音源记忆由设置页提供入口

## 中途卡播恢复链

### 触发条件

- `buffering` 长时间无进展
- 播放位置长期不推进
- 媒体源切换失败
- 官方源返回空地址或失效

### 恢复步骤

1. 进入 `buffering` 态
2. 冻结系统媒体时间轴
3. 启动无进度 watchdog
4. 标记当前音源失败
5. 同源重连并尝试保留当前进度
6. 若同源重连失败则解析下一候选音源
7. 成功后恢复到最后稳定位置
8. 若候选耗尽则跳到下一首并记录失败原因

### watchdog 生命周期

- watchdog 不能常驻
- 只有在以下条件同时满足时才允许运行：
  - 当前存在活动歌曲
  - 播放器处于 `buffering`
  - 用户意图仍然是继续播放，也就是 `playWhenReady=true`
- 任一条件失效都必须立即停止 watchdog，避免无意义唤醒

## 进度策略

- 只有真实进度推进时才刷新 UI 时间轴
- 缓冲态必须冻结 `positionMs`
- 切源态必须冻结系统媒体条
- 恢复完成后再继续推进
- 不允许在缓冲期间系统时间轴自行推进

## 评论与歌词生命周期

- 评论加载和歌词加载必须与音频主线程解耦
- 评论分页不能阻塞播放恢复链
- 歌词滚动不能反向驱动音频时间轴
- 评论、歌词、队列的加载失败只能影响各自区域，不能中断音频播放
- 歌词数据进入 UI 前要先做头尾元信息清洗，常见 `Lyrics provider / Translation provider / Cloud Drive / 作词作曲` 这类说明行不能继续污染首尾对齐和歌词空态判断
- 播放详情允许在歌曲元数据与歌词到位后，对评论首屏做单次后台预热
- 评论预热只能命中缓存填充和一次性请求，抽屉未打开前不能维持持续刷新

## 歌词交互状态机

- 歌词页固定为两态：
  - 自动跟随态
  - 手动预览态
- 逐字歌词在存在字级时间数据时必须优先使用：
  - `yrc`
  - QQ `qrc`
  - TTML 内带 `begin / end` 的字级片段
  - 网易云 `yrc` 的字开始时间按绝对毫秒解释，和 desktop 现有语义保持一致，不能再额外叠加行起始时间
- 自动跟随态下，当前行允许逐字高亮：
  - 已经过时的字保持高亮
  - 当前推进中的字按时间进度逐字推进，不允许整词整段一起跳亮
  - 未到时的字保持低亮
- 没有字级时间时才允许退回逐句高亮，不能伪造逐字动画，也不能继续维持真逐字刷新频率
  - 自动跟随态：
    - 当前播放行自动居中跟随
    - 首句、末句和中间行必须共享同一视觉中线
    - 歌词正文必须限制在独立居中的内容块宽度内，不能直接铺满整屏
    - 只允许退回逐句级高亮和较低刷新频率，不能因为普通 LRC 继续维持真逐字节拍
    - 点击任意歌词行或空白区域直接返回封面
- 手动预览态：
  - 由用户主动滚动歌词触发
  - 程序自己的自动居中滚动不能误触发手动预览态
  - 自动跟随暂停
  - 视区中部生成预览锚点
  - 预览锚点必须脱离歌词行本体独立悬浮，不能把时间戳和播放按钮直接塞回当前歌词行
  - 预览锚点必须展示目标时间戳和跳转按钮
  - 只有点击当前预览锚点才执行 `seekTo`
  - 点击其他歌词行或空白区域仍返回封面
- 预览锚点触发 seek 后必须退出手动预览态，重新回到自动跟随态
- 歌词交互只能驱动播放器 seek，不能驱动播放状态机进入额外刷新循环

- 失败音源记忆：已实现
- 动态重试上限：已实现
- 模拟器坏解码器过滤：已实现

- 封面 / 歌词单轴切换：已实现基础流
- 封面态响应式黑胶布局：已实现基础流，已移除固定封面高度和固定黑胶尺寸，并按屏宽 / 可用高度联合上探黑胶主视觉，同时恢复播放中的黑胶旋转

- 歌词元信息剥离：已实现基础流，歌词进入 UI 前会先清掉常见头尾 provider / credit 行
- 逐字歌词高亮：已实现基础流，当前优先吃 `yrc / qrc / TTML` 的字级时间片段，并在单词内部继续按字推进
- 普通 LRC 刷新节拍：已收口为逐句级节拍，只有命中字级时间片段时才升到逐字刷新

- 评论首屏预热：已实现基础流，未打开评论抽屉时会优先复用缓存并做一次性后台补齐
