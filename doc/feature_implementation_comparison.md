# Android V1 功能实现对照

| Spec 项                        | 当前实现                                                                                                                                                | 状态     | 偏差                                                                          | 根因                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Android 独立 App               | 已接入 Capacitor Android，包名为 `top.imsyy.splayer`，应用名为 `SPlayer`，静态资源输出到 `dist_mobile` 并内置到 Android 工程                            | 已实现   | 仍为轻壳 WebView，不做原生页面重写                                            | V1 目标是先完成可运行轻壳与移动端收口，避免为原生壳重写引入过大成本 |
| 独立构建链                     | `package.json` 已区分 `build:web`、`build:mobile`、`cap:sync`、`cap:open`，Capacitor `webDir` 指向 `dist_mobile`                                        | 已实现   | `build:web` 仍复用现有 Electron Web 构建链                                    | 桌面 Web 产物仍服务现有发布链，V1 只拆出移动端构建链即可            |
| Oracle API 直连                | 移动端构建保持独立 `mobile` mode，现有配置已支持移动端单独产物                                                                                          | 已实现   | API 地址仍依赖环境变量注入，不在仓库里写死                                    | 保持部署环境可切换，避免把测试地址固化到源码                        |
| 登录态持久化                   | 继续使用现有 Cookie 与本地存储方案，独立 App 容器不再受浏览器私密模式影响                                                                               | 已实现   | 未引入 Android 原生安全存储                                                   | V1 只要求重开 App 后可复用登录态，不要求原生凭据托管                |
| 系统分享                       | 新增统一平台层 `src/utils/platform.ts`，分享链路为 Capacitor Share -> Web Share -> 剪贴板降级，并已接入歌曲、封面、歌单、专辑、歌手、电台等主要入口     | 已实现   | 仍保留少量“复制信息”类弹窗，未强制改成系统分享                                | 复制信息属于编辑/导出类操作，不属于 Spec 中要求的系统分享核心链路   |
| 外链走系统浏览器               | 新增统一外链打开入口，Capacitor 下走 `@capacitor/browser`，Web 保留 `window.open` 降级；关于页、更新页、设置页、详情源页与 Last.fm 授权已切换到统一入口 | 已实现   | Last.fm 在 Capacitor 下改为系统浏览器授权后轮询会话，不再依赖内嵌弹窗关闭事件 | 系统浏览器是 Android 更稳定的授权方式，内嵌 Web 弹窗在移动端不可控  |
| ESLint 工程基线                | 已补齐忽略规则，仅排除 `dist_mobile` 与 Android 复制出的 Web 产物，恢复真实源码 lint                                                                    | 已实现   | Android 同步产物仍会落进仓库工作树                                            | Capacitor `sync` 会复制前端产物，忽略生成目录比删除产物更稳妥       |
| 顶部与底部安全区               | 全局样式已补 `100dvh`、安全区高度、窄屏溢出保护；底部播放器增加安全区内边距                                                                             | 已实现   | 仍依赖各页面已有容器结构，未彻底统一为单一壳组件                              | 当前仓库页面层级较深，V1 先用全局样式和高频页面收口降低改动面       |
| 页面滚动与底部播放器避让       | 列表详情、搜索建议、默认搜索结果、设置页等关键区域已增加移动端高度与留白处理，底部悬浮按钮位置也已下移                                                  | 已实现   | 首页与少量 P1 页面主要继承现有布局，没有单独重写容器                          | 优先修复 P0 高频页面，次级页面沿用现有响应式布局                    |
| 搜索页可用性                   | 搜索框移动端改为稳定全宽，聚焦不再横向顶出；建议层与默认结果层增加视口宽高约束，避免键盘和弹层遮挡                                                      | 已实现   | 仍依赖浏览器/WebView 对键盘 resize 的行为                                     | 软键盘行为最终由 Android WebView 控制，前端只能约束容器尺寸         |
| 播放页可用性                   | 主播放器底栏增加安全区，歌曲“更多操作”与右侧控制在小屏切到底部抽屉，避免桌面下拉菜单超屏                                                                | 已实现   | 未新增原生锁屏控件、后台播放服务                                              | 这些能力在 Spec 中明确属于非目标                                    |
| 列表与详情页可用性             | 歌曲列表排序、详情页更多操作在小屏下改为底部抽屉；详情区搜索和分段控件改成可换行/可压缩布局                                                             | 已实现   | 首页卡片流未做结构性改版                                                      | 列表和详情是 Android V1 高频路径，首页视觉改版收益低于收口成本      |
| 登录页 / 二维码页              | 登录主弹窗、UID/Cookie 子弹窗、短信验证码表单、二维码尺寸都已加移动端约束，按钮改为纵向可点布局                                                         | 已实现   | 仍沿用现有双 Tab 登录方案                                                     | 现有登录逻辑稳定，改交互形态比改登录流程风险更低                    |
| 设置页可用性                   | 设置页移动端保持覆盖层 + 侧栏抽屉结构，主弹窗在小屏下改为全屏卡片，表单区增加底部安全区与纵向留白                                                       | 已实现   | 仍保留桌面信息架构，没有拆成多级移动路由                                      | 在不改路由的前提下，全屏设置弹窗是风险最低的可用化方案              |
| Popover / Modal 改为移动端弹层 | 新增响应式弹层策略，小屏下主要入口统一切换为 `n-drawer` 或窄宽度 `n-modal`                                                                              | 已实现   | 仍有部分 P2 低频弹窗保持桌面卡片样式，但已受全局响应式宽度约束                | 低频配置页不值得在 V1 批量重构为独立 Bottom Sheet                   |
| 首页可正常浏览                 | 现有首页继续复用原有响应式布局，并共享全局安全区与横向溢出修复                                                                                          | 部分实现 | 未对首页做单独 Android 样式重写                                               | 本轮优先级集中在 Spec 明确点名的 P0 交互热点                        |
| 歌词页可用                     | 播放器相关移动端适配已覆盖底栏与更多操作，但歌词页本身未单独重构布局                                                                                    | 部分实现 | 仍沿用现有全屏歌词结构                                                        | 现有歌词布局基本可用，本轮优先解决遮挡与操作超屏问题                |
| P1/P2 页面精修                 | 关于页与更新页已接入外链桥接，其他评论区、历史记录、调试入口等页面未做系统性移动精修                                                                    | 部分实现 | 主要完成桥接与防超屏兜底，没有逐页打磨                                        | 依照 Spec 优先级，P1/P2 只做能用与不出屏，不做精修                  |
| 非目标能力                     | 后台原生播放、锁屏媒体控制、原生下载管理、分享接收、iOS 适配均未实现                                                                                    | 未实现   | 与 Spec 保持一致                                                              | 这些能力超出 Android V1 范围，提前接入会显著放大测试与维护成本      |

## 结论

当前实现已经覆盖 Android V1 的核心交付面：轻壳构建、登录持久化、系统分享、外链桥接，以及搜索、播放、详情、设置、登录等 P0 页面的小屏交互收口。剩余未精修部分主要集中在首页、歌词页和 P1/P2 次级页面的视觉细节与真机回归验证。
